# feature / integration

## 何时读取
仅在以下场景读取并执行本文件：

- 改动涉及数据库写入
- 改动涉及数据库迁移或 Schema 变化
- 改动涉及跨服务联调
- 需要真实环境验证而非仅本地静态/单元校验

## 执行要求
1. 自行判断需要的隔离级别：涉及真实数据库、外部服务的操作不应在宿主环境直接运行。
2. 使用 Docker 启动所需的外部服务（PostgreSQL、Redis、MinIO 等），在隔离环境中完成验证。
3. 只有在隔离验证通过后，才允许继续整理提交和合并回主目录。
4. 若隔离验证持续失败且无法自主修复，按 `stop-conditions.md` 处理。
