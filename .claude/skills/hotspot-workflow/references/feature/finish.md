# feature / finish

## 何时读取
在实现和本地校验完成后读取本文件；若任务需要进入“准备合并”状态，则先完成必要的隔离验证再继续。

## 执行要求
1. 先确认当前结果满足“开发完成”或“准备合并”的目标状态。
2. 若改动涉及数据库写入、迁移、跨服务联调或真实环境链路，先运行 `integration.md` 中的隔离验证，再继续收尾。
3. 查看领先 `main` 的提交，确保最终只保留一个语义清晰的 commit。
4. 最终 commit message 必须符合 `<type>(<scope>): <subject>`。
5. 切回主目录，基于最新可用的 `main` 进行线性同步。
6. 通过 `git merge --ff-only` 将该单个 commit 合并回本地 `main`；若失败，先把分支 rebase 到 `main` 后重试。
7. 合并完成后，删除本次使用的临时 worktree 与临时分支。
8. 仅在实现、测试、合并、清理都完成后，才向用户汇报结果。

## 完成标准
- 实现与必要测试已完成。
- 已达到目标验证级别：仅本地校验通过，或在需要时 `verify.sh` 也已通过。
- 本地 `main` 新增一个符合规范的 commit。
- worktree 和临时分支已清理。
