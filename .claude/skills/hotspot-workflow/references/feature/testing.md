# feature / testing

## 何时读取
在实现完成后、进入本地校验阶段时读取本文件。

## 环境约束
- 所有校验命令**必须在 worktree 目录内执行**，不得切回宿主主目录。
- 若 worktree 内缺少必要工具链且无法安装，视为阻塞并报告给用户。

## 校验范围
本阶段对应“开发完成”状态：优先完成与本次改动直接相关、且不依赖外部服务的本地校验。
若子项目 `CLAUDE.md` 已定义更完整的本地命令集，应根据改动风险补充执行，而不是机械固定为最低命令组合。

当前 `verify.sh` 的隔离验证主要覆盖 `backend-go/` 与 `frontend_svelte/`；`backend/` 与 `harmonyapp/` 暂无同等 deploy-backed 隔离入口。

## 各子项目默认最低校验

- `backend/`：`cargo test`
- `backend-go/`：`go test -short ./...`（`-short` 跳过需要外部服务的集成测试）
- `frontend_svelte/`：`pnpm check && pnpm build`
- `harmonyapp/`：运行当前环境可用的 Harmony 校验命令；若工具链缺失且无法完成必要校验，则视为阻塞

## 补充规则
- 若子项目 `CLAUDE.md` 明确定义了与当前改动直接相关的 `lint`、单元测试或构建命令，应按风险补跑。
- 最低校验不等于完整校验；“开发完成”强调相关性与可执行性，“准备合并”再按风险升级。
- 补齐与本次改动直接相关的必要测试。
- 只要某个受影响子项目存在本地可执行校验，就不能跳过。
- 若测试失败，优先修复实现或测试本身，而不是绕过校验。
- 若失败原因是缺少数据库 / Redis 连接，说明这些是集成测试，跳过并转由 `verify.sh` 验证。
- 若当前任务只是 `L1` 局部改动，以相关本地校验通过作为默认完成条件；不要默认升级到隔离验证。
