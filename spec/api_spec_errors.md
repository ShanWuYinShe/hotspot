# HotSpot API - 错误码定义

> 本文档定义 HotSpot API 的所有错误码，包括 HTTP API 业务错误码、WebSocket 业务期错误码和幂等性相关错误码。
> 本文件是错误码的唯一权威来源。

## 设计原则

错误码的职责是告诉客户端**该做什么**（刷新 token / 跳登录 / 显示提示 / 重试），而不是**发生了什么**。

- **`code`** 驱动客户端分支逻辑（刷新 token? 跳登录页? 显示 toast? 等待重试?）
- **`message`** 描述具体业务场景（"用户不存在"、"群组已满员"、"密码错误"等），由后端根据场景动态生成
- 客户端**禁止**解析 `message` 来决定行为，只用于展示

## 错误码定义

本系统 `ApiResponse.code` 为**稳定业务错误码**，与 HTTP 状态码**无任何绑定关系**。
仅当 HTTP 状态码为 200 时才返回 `ApiResponse`；HTTP 非 200 视为请求失败（未进入业务层）。

失败响应（`code != 0`）必须包含 `message`，并且 `data` 必须省略（除非端点显式声明错误时 data 的结构）。
请求追踪通过响应头 `X-Request-Id` 提供。

**使用规范**：
- 各模块错误码说明表必须按错误码升序排列
- 说明字段必须使用本文件的标准描述，必要时可在括号内补充接口级语义
- 编号间隙为预留空间，禁止随意填补

### 隐含错误码（无需在端点重复列出）— 权威清单

以下错误码为**所有端点隐含支持**（由中间件/全局处理层产生），各模块端点文档的"错误码"字段**禁止重复列出**它们，只列该端点**特有**的业务错误码。若某端点的错误码小节出现了下列隐含码，视为文档缺陷。

| 错误码 | 隐含适用范围 |
|-------|-------------|
| `10100` | 所有"认证: 必须"的端点（缺少/无效 token） |
| `10201` | 所有"认证: 必须"的端点（账号被封禁，中间件级检查） |
| `10500` | 所有端点（触发限流） |
| `10600` | 所有端点（服务端错误/系统不可用） |
| `22000` / `22001` / `22002` | 所有可能返回幂等键相关错误的端点（即需要实现幂等的端点） |

> 此清单是 `api_spec_base.md`「通用隐含错误码」小节的权威来源。模块端点只需列出业务特有码（如 `10000`/`10200`/`10300`/`10400` 等及模块专属码）。

## HTTP API 业务错误码（10000-19999）

| 错误码 | 类型 | 客户端行为 | message 示例 |
|-------|------|-----------|-------------|
| `10000` | 参数错误 | 显示 message，引导用户修正输入 | "缺少必填参数: login_id"、"参数格式错误: phone"、"请求体过大" |
| `10100` | 认证失败 | 中间件尝试刷新 token；失败则跳登录页；登录表单场景直接显示 message | "Access Token 无效或过期"、"密码错误"、"验证 Token 已过期" |
| `10200` | 权限不足/访问受限 | 显示 message | "非系统管理员"、"对方隐私设置不允许"、"对方不允许被关注" |
| `10201` | 账号被封禁 | **强制登出** + 显示封禁页 | "账号被封禁: 违规操作" |
| `10300` | 资源不存在 | 显示"不存在"提示 | "用户不存在"、"群组不存在"、"消息/会话不存在" |
| `10400` | 业务冲突 | 显示 message | "资源已存在"、"群组已满员"、"消息已被撤回"、"不是群组成员" |

**`10400` 适用边界**：仅用于**真正无法完成**的状态冲突（创建已存在资源、满员、撤回超时、权限前置不满足等）。对于**设状态操作重复达同状态**（如 unfollow 已未关注、unban 未封禁、set_role 设成相同角色），应返回成功（no-op），**不得**使用 `10400`——这与 Discord（no-op 返回 204）、HTTP PUT（no-op 返回 200）等业界共识一致。
| `10500` | 请求过于频繁 | 按 `Retry-After` 响应头等待后重试 | "超过每分钟请求限制"、"消息数量已达上限" |
| `10600` | 服务器错误/系统不可用 | 显示"服务异常"提示 | "服务器内部错误"、"服务暂时不可用"、"系统维护中" |

**`10201` 独立保留的理由**：账号封禁需要客户端强制登出并展示专用封禁页面，这与普通权限不足（仅显示 toast）的客户端行为**本质不同**，无法通过解析 message 安全判断。

**安全说明**：
- 服务端内部错误统一返回 `10600`，禁止向客户端暴露具体技术细节（如堆栈、SQL、内部路径等）
- `system/health` 端点将 `10600` 用于主动上报 `unhealthy` 状态，属于约定内的系统不可用语义
- 参数错误（`10000`）的 `message` 中引用的字段名**必须**与 API 契约中的字段名一致（如 `login_id`、`nickname`），**禁止**暴露数据库列名（如 `user_login_name`）或内部变量名

**预留区间**：`10601-19999` 为 HTTP API 预留业务错误码区间，用于未来业务模块扩展，当前禁止使用。

## WebSocket 连接后业务阶段错误码（20000-20999）

WebSocket 握手成功必须为 HTTP 101；握手失败使用真实 HTTP 状态码。本节错误码用于连接建立后的业务期（Auth、订阅、业务消息等）。

| 错误码 | 类型 | message 示例 |
|-------|------|-------------|
| `20000` | 连接/协议错误 | "鉴权失败"、"心跳超时"、"消息格式错误"、"协议不兼容" |
| `20100` | 订阅错误 | "订阅频道不存在"、"订阅权限不足"、"订阅数量超出限制" |
| `20200` | 消息错误 | "消息内容过长"、"消息格式错误"、"消息发送频率过高" |
| `20300` | 限流 | "触发限流"、"请求过于频繁" |
| `20400` | 权限错误 | "无权限"、"操作受限"、"群组已解散" |
| `20500` | 服务端错误 | "内部错误"、"服务暂时不可用" |

**预留区间**：`20501-20999` 为 WebSocket 预留错误码区间，当前禁止使用。

## 幂等性相关错误码（22000-22099）

各自驱动不同的客户端重试策略，不合并。

| 错误码 | 类型 | 客户端行为 | message 示例 |
|-------|------|-----------|-------------|
| `22000` | 幂等键冲突 | 换新的 Idempotency-Key 重试 | "幂等键格式无效"、"幂等上下文不匹配" |
| `22001` | 幂等缓存失效 | 换新的 Idempotency-Key 重试 | "幂等缓存已过期，请使用新的幂等键重试" |
| `22002` | 幂等操作进行中 | 等待 1-2 秒后使用相同 Idempotency-Key 重试 | "操作处理中，请稍后重试" |

**触发场景说明**：
- `22000`：幂等键无效或不可恢复冲突（如格式不合法、幂等上下文不匹配）
- `22001`：幂等缓存已过期或已清理，服务端无法回放历史响应
- `22002`：同一幂等键对应请求仍在处理中

**预留区间**：`22003-22099` 为幂等性预留错误码区间，当前禁止使用。

---

## 编号分区总览

| 区间 | 用途 |
|------|------|
| `10000-10600` | HTTP API 业务错误码 |
| `10601-19999` | HTTP API 预留（当前禁止使用） |
| `20000-20500` | WebSocket 业务期错误码 |
| `20501-20999` | WebSocket 预留（当前禁止使用） |
| `21000-21999` | WebSocket 协议扩展预留（如未来多端同步、实时协作等新协议场景；当前禁止使用，避免与 2xxxx 段语义混淆） |
| `22000-22099` | 幂等性相关错误码 |
